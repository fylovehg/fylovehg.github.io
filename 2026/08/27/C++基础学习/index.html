vector的扩容机制

vector 维护了一块连续的内存空间，用三个指针来管理：

指针 作用
_M_start 指向数组的起始位置（第一个元素）
_M_finish 指向已使用空间的末尾（最后一个元素的下一个位置）
_M_end_of_storage 指向整块分配内存的末尾（容量的边界）

  • size（大小）：当前已经存了多少个元素 = finish - start

  • capacity（容量）：总共能存多少个元素（不重新分配的情况下）= end_of_storage - start
    当空间不足需要扩容时，vector 会执行以下步骤：

  • 步骤 1：分配一块更大的新内存

  • 新容量通常是旧容量的 1.5 倍或 2 倍（取决于编译器实现）

  • GCC（libstdc++）：2 倍

  • MSVC（Visual Studio）：1.5 倍

  • Clang（libc++）：2 倍

  • 步骤 2：把旧元素拷贝 / 移动到新内存

  • C++11 之前：逐个拷贝构造元素

  • C++11 之后：如果元素的移动构造函数是 noexcept 的，就用移动（更快）；否则用拷贝

  • 步骤 3：销毁旧内存中的元素

  • 调用旧元素的析构函数

  • 步骤 4：释放旧内存，更新三个指针

  • 释放旧的内存空间

  • 把 start、finish、end_of_storage 指向新内存的对应位置

指针加1内存的位移量

核心结论：指针加一，地址增加的不是 1 字节，而是 sizeof(指向的类型) 字节。

原理：

指针的类型决定了它的 “步长”—— 加一时跳过多少字节。这样设计是为了让 p+1 自然地指向下一个同类型元素。

常量指针vs指针常量

这是 C/C++ 指针部分最经典、最容易搞混的考点。核心就一句话：看 const 在 * 的左边还是右边。

  • 两个概念的本质区别
名称 英文 写法 本质 指针本身能改吗？ 指向的值能改吗？
常量指针 pointer to const const int* p / int const* p 指向 “常量” 的指针 ✅ 能改指向 ❌ 不能改值
指针常量 const pointer int* const p 指针本身是 “常量” ❌ 不能改指向 ✅ 能改值
都常量 const pointer to const const int* const p 指向常量的常量指针 ❌ 不能改指向 ❌ 不能改值

指针和数组

在 C/C++ 底层，根本没有 “数组” 这个东西，只有指针和连续内存。数组是编译器为了方便人类理解，在指针基础上包装出来的语法糖。

  1. 数组名本质上是一个指针（指向首元素）

关键结论：

  • 数组名 a 的值就是首元素 a[0] 的地址
  • a[i] 和 *(a+i) 完全等价
  • 指针 p 也可以用 p[i] 的写法，和 *(p+i) 等价
  1. ⚠️ 数组名和普通指针的区别（重点！）

虽然数组名本质上是指针，但它和普通指针不完全一样：

表格

对比项 数组名 a 普通指针 p
本质 首元素地址（常量指针） 指针变量
sizeof 整个数组的大小（如 int a[5] → 20 字节） 指针本身的大小（8 字节 / 64 位）
能否改指向 ❌ 不能，a = &x 编译错误 ✅ 可以，p = &x
能否自增 ❌ 不能，a++ 编译错误 ✅ 可以，p++

💡 视频里提到的 sizeof(a) = 20 而 sizeof(p) = 8，就是这个原因。数组名虽然值是地址，但它的 “类型” 是数组类型，不是指针类型。
