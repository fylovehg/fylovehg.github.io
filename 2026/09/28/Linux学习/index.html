chmod命令

chmod +r 是 Linux 中用于给文件或目录添加读取权限的命令。

  1. 命令含义
    chmod +r 文件名
  • chmod：修改文件或目录的权限（change mode）。
  • +：增加权限。
  • r：读取权限（read）。
  • 文件名：需要修改权限的文件。
    例如：
    chmod +r test.txt

表示：给 test.txt 文件增加读取权限。
2. Linux 常见权限

  1. 如何查看文件权限？
    输入：
    ls -l test.txt

例如显示：
-rwxr–r– 1 root root 100 Oct 10 12:00 test.txt

  1. 注意区别
    chmod +r 默认给所有用户类别增加读取权限，但受系统 umask 等规则影响。
    如果只想给文件所有者添加读取权限：
    chmod u+r test.txt

如果给所有用户明确添加读取权限：
chmod a+r test.txt

网络编程基础

网络中的地址

一、单播、广播和组播

    1. 基本概念
通信方式 英文名称 含义 举例
单播 Unicast 一对一通信 PC1 向 PC2 发送数据
广播 Broadcast 一对同一广播域内所有设备通信 ARP 请求
组播 Multicast 一对多通信，向指定组播组发送数据 IPTV、视频会议
    1. 组播的工作原理

组播是一种网络层提供的一对多通信方式。

注意：组播不是 TCP/UDP 上面的广播，而是 IP 层的一种通信方式。

  • TCP：主要提供可靠的一对一通信，不直接支持 IP 组播。
  • UDP：常与 IP 组播配合使用。
  • IP 组播：向特定组播地址发送数据，由网络设备根据组播成员关系转发。

举例

假设有 100 台电脑需要观看同一个直播。

单播方式：

服务器需要分别向 100 台电脑发送数据。

如果每路直播需要 5 Mbps：

服务器总发送带宽约为：

100 × 5 Mbps = 500 Mbps

组播方式：

服务器只需要向组播组发送一份数据，网络设备根据需要复制并转发。

服务器发送该直播流所需的带宽约为 5 Mbps。

注意：组播并不意味着整个网络中只有一份数据，而是避免在共享链路上重复发送相同的数据。

结论：组播可以有效减少重复传输，节约网络带宽。

    1. 组播的缺点

组播如果配置不当，可能出现组播泛洪问题。

广播风暴

大量广播帧持续在网络中传播，导致网络拥塞，严重时影响正常通信。

组播泛洪

交换机不知道哪些端口需要接收组播数据时，可能把组播流量转发到不需要的端口。

解决方法

启用 IGMP Snooping。

作用：

  • 监听组播成员关系信息。
  • 判断哪些端口存在组播接收者。
  • 减少不必要的组播流量转发。
  • 提高网络带宽利用率。

注意：

组播泛洪不等于广播风暴，组播本身也不一定导致网络风暴。

二、IPv4 地址分类

IPv4 地址在传统分类编址中分为 A、B、C、D、E 五类。

    1. A、B、C、D、E 类地址
类别 地址范围 主要用途 默认子网掩码
A 类 1.0.0.0～126.255.255.255 传统大型网络 255.0.0.0
B 类 128.0.0.0～191.255.255.255 传统中型网络 255.255.0.0
C 类 192.0.0.0～223.255.255.255 传统小型网络 255.255.255.0
D 类 224.0.0.0～239.255.255.255 组播 无
E 类 240.0.0.0～255.255.255.255 保留、实验用途 无

注意：

  1. A 类、B 类、C 类主要用于传统单播网络编址。
  2. D 类用于组播，不等于广播。
  3. E 类主要为保留用途，不是通常意义上的私有网络地址。
  4. 255.255.255.255 是特殊的受限广播地址。
  5. 现代网络主要使用 CIDR 无类别编址，不再依赖 A、B、C 类默认掩码。
    1. 私有 IP 地址

私有 IP 地址主要用于局域网。

类别 私有地址范围 CIDR 表示
A 类范围 10.0.0.0～10.255.255.255 10.0.0.0/8
B 类范围 172.16.0.0～172.31.255.255 172.16.0.0/12
C 类范围 192.168.0.0～192.168.255.255 192.168.0.0/16

常见例子：

  • 192.168.1.1：家庭路由器常用地址。
  • 192.168.1.100：局域网电脑可能使用的地址。
  • 10.0.0.1：企业内部网络常见地址。

注意：

私有 IP 地址不能直接在公网中进行普通路由转发。

家庭网络通常通过 NAT 技术访问互联网。

127.0.0.1 称为回环地址（Loopback Address）。

主要用于本机通信和测试。

举例

如果本机网络协议栈正常且允许 ICMP 回应，通常可以收到回复。

工作原理

当数据发送到 127.0.0.1 时：

  1. 操作系统识别目标地址为回环地址。
  2. 数据在本机网络协议栈内部处理。
  3. 数据不经过物理网卡发送到外部网络。
  4. 如果目标服务或协议能够响应，则产生相应回复。

注意：

并不是向 127.0.0.1 发送任何数据都会原样返回。

例如，ping 能收到回复，是因为 ICMP 协议栈对 Echo Request 进行了响应。

回环地址范围

整个地址段都属于回环地址范围。

127.0.0.1 是最常使用的回环地址。

    1. 255.255.255.255

255.255.255.255 是受限广播地址。

作用：

向本地网络进行广播。

特点：

  • 广播域内的设备可以接收相应广播数据。
  • 路由器不会把这种受限广播转发到其他网络。

常见应用：

DHCP 客户端在尚未获得 IP 地址时发送广播请求。

0.0.0.0/0 默认路由 匹配没有更具体路由的目的地址
127.0.0.1 回环地址 访问本机、测试网络协议栈
255.255.255.255 受限广播地址 本地广播

记忆方法

0.0.0.0：所有本机 IPv4 地址（服务器绑定场景）

127.0.0.1：我自己

255.255.255.255：本地所有设备（受限广播）

    1. 容易出错的知识点

错误一：组播就是 TCP/UDP 上面的广播。

正确：组播属于 IP 层的通信方式，通常与 UDP 配合使用。

错误二：组播一定会产生网络风暴。

正确：组播本身不一定产生网络风暴，配置不当可能导致组播泛洪。

IP 地址用于确定网络中的主机，端口号用于区分主机上的不同网络服务或通信端点。

二、端口的三大分类

根据 IANA 的端口号分配规则，端口主要分为三类。

端口类型 英文名称 端口范围
公认端口 Well-Known Ports 0～1023
注册端口 Registered Ports 1024～49151
动态/私有端口 Dynamic/Private Ports 49152～65535
    1. 公认端口（Well-Known Ports）

端口范围：

公认端口也称为知名端口或常用端口。

这类端口通常分配给一些标准网络服务。

例如：

  • 80：HTTP。
  • 443：HTTPS。
  • 21：FTP 控制连接。
  • 22：SSH。
  • 23：Telnet。
  • 25：SMTP。

特点：

  1. 通常用于常见网络服务。
  2. 端口号与特定协议或服务存在约定关系。
  3. 客户端通常根据默认端口访问相应服务。
  4. 在 Linux 等系统中，绑定小于 1024 的端口通常需要相应权限。

注意：

端口号与服务并不是绝对绑定的。

例如：

HTTP 默认使用 TCP 80，但也可以配置为 TCP 8080。

HTTPS 默认使用 TCP 443，也可以配置其他端口。

此外，端口 0 是保留端口，不是普通服务的默认监听端口。

    1. 注册端口（Registered Ports）

端口范围：

注册端口通常由软件厂商或开发者为特定应用程序注册使用。

特点：

  1. 可以用于各种应用服务。
  2. 部分端口已有约定用途。
  3. 也可以用于自行开发的网络程序。
  4. 不同软件可能使用不同的端口配置。

常见例子：

端口 常见服务
1433 Microsoft SQL Server
1521 Oracle 数据库
3306 MySQL
3389 Windows 远程桌面 RDP
5432 PostgreSQL
6379 Redis
8080 HTTP 备用端口，常用于 Web 服务

注意：

端口被注册或约定使用，不代表其他程序在技术上完全不能使用该端口。

但在同一 IP 地址、传输协议及相应绑定条件下，程序可能因端口冲突而无法同时监听。

端口范围：

主要用于客户端临时建立网络连接。

六、端口与网络安全

端口本身并不具有安全或危险属性。

不能认为：

  • 公认端口一定安全。
  • 注册端口一定不安全。
  • 动态端口一定是木马使用的端口。

恶意程序可能使用任何端口进行通信。

例如：

恶意程序也可能使用 TCP 443 伪装成普通 HTTPS 流量。

因此，判断网络通信是否安全，需要结合：

  1. 端口对应的进程。
  2. 网络连接的目标地址。

网络协议（Protocol）

一、什么是协议

协议（Protocol）是计算机之间进行网络通信时必须遵守的一套规则。

简单理解：

协议就是规定计算机之间如何进行通信。

例如，两个人打电话需要遵守一定的规则：

  1. 双方使用能够理解的语言。
  2. 一方发送信息，另一方接收信息。
  3. 没听清楚时可以要求重复。
  4. 通信结束后挂断电话。

计算机之间通信同样需要规则。

网络协议主要规定：

  • 数据采用什么格式。
  • 数据如何发送。
  • 接收方如何识别和处理数据。
  • 数据丢失时如何处理。
  • 如何建立和结束通信。

注意：不同协议负责不同的功能，并不是所有协议都提供重传、连接建立等机制。

三、TCP 和 UDP 协议

TCP 和 UDP 都属于传输层协议。

    1. TCP（Transmission Control Protocol）

中文名称：传输控制协议。

TCP 是一种面向连接、可靠的传输层协议。

主要特点：

  1. 通信前需要建立连接。
  2. 通过确认、序列号和重传等机制实现可靠传输。
  3. 保证数据按顺序交付给应用程序。
  4. 提供流量控制。
  5. 具有拥塞控制机制。

常见应用：

  • HTTP/1.1、HTTP/2
  • 传统 HTTPS
  • FTP
  • SSH
  • SMTP

举例：

TCP 类似于打电话。

双方先建立连接，然后进行通信。

如果传输过程中发生数据丢失，TCP 可以通过重传机制恢复数据。

    1. UDP（User Datagram Protocol）

中文名称：用户数据报协议。

UDP 是一种无连接的传输层协议。

主要特点：

  1. 通信前不需要建立传输层连接。
  2. 不保证数据一定送达。
  3. 不保证数据按顺序到达。
  4. 不提供 TCP 那样的内置重传机制。
  5. 协议头部较小，开销较低。

常见应用：

  • DNS 查询
  • DHCP
  • 实时音视频
  • 网络游戏
  • QUIC（HTTP/3 使用的传输协议）

举例：

UDP 类似于寄明信片。

发送方直接发送数据，不需要事先建立连接。

但不能保证数据一定到达。

注意：

UDP 本身不保证可靠性，但应用程序可以在 UDP 之上自行实现确认、重传等可靠传输机制。

TCP协议基础

一、TCP 协议基本概念

TCP（Transmission Control Protocol）中文名称为传输控制协议。

TCP 属于传输层协议，主要负责在网络中的两个通信端点之间提供可靠、有序的字节流传输。

TCP 的三个核心特点

  1. 面向连接：通信前需要建立连接。
  2. 可靠传输：通过确认、重传等机制保证数据可靠、有序地交付。
  3. 面向字节流：传输连续字节，不保留应用程序发送消息的边界。

例如：

原因：TCP 是面向字节流的协议。

二、TCP 三次握手（重点）

TCP 建立连接通常需要三次握手。

  1. 三次握手过程

第一次握手：客户端发送 SYN。

  • 请求建立 TCP 连接。
  • 客户端进入 SYN-SENT 状态。

第二次握手：服务器发送 SYN + ACK。

  • 确认收到客户端的 SYN。
  • 发送服务器自己的 SYN。
  • 服务器进入 SYN-RECEIVED 状态。

第三次握手：客户端发送 ACK。

  • 确认收到服务器的 SYN。
  • 客户端进入 ESTABLISHED 状态。
  • 服务器收到有效 ACK 后进入 ESTABLISHED 状态。
  1. 为什么需要三次握手

主要原因：

  1. 交换并确认双方的初始序列号。
  2. 确认双方能够正常交换建立连接所需的信息。
  3. 避免旧的重复连接请求造成混乱。
  1. 三次握手记忆

记忆口诀：

请求连接 → 同意并确认 → 再次确认。

三、TCP 四次挥手（重点）

TCP 正常断开连接时，典型过程是四次挥手。

  1. 四次挥手过程

第一次挥手：

主动关闭方发送 FIN，表示自己没有更多数据要发送。

第二次挥手：

被动关闭方发送 ACK，确认收到 FIN。

第三次挥手：

被动关闭方完成剩余数据发送后，发送 FIN。

第四次挥手：

主动关闭方发送 ACK，确认收到 FIN。

  1. 为什么通常需要四次挥手

因为 TCP 是全双工通信。

两个方向的数据传输可以分别关闭。

收到对方的 FIN，并不代表自己已经发送完数据。

因此，确认对方的 FIN 和发送自己的 FIN 通常是两个独立步骤。

注意：

第二次 ACK 和第三次 FIN 有时可以合并发送，因此实际关闭过程不一定恰好有四个独立报文段。

  1. 四次挥手记忆

记忆口诀：

我要关闭 → 收到 → 我也关闭 → 收到。

滑动窗口用于提高数据传输效率。

八、TCP 拥塞控制

拥塞控制主要解决：

网络中的数据太多，导致网络拥塞。

TCP 根据网络状态调整发送量。

常见拥塞控制概念：

  1. 慢启动。
  2. 拥塞避免。
  3. 快速重传。
  4. 快速恢复。
  1. 慢启动

连接开始时，拥塞窗口通常较小。

随着成功确认数据，逐步增加发送量。

  1. 拥塞避免

当拥塞窗口达到一定阈值后，通常采用相对缓慢的增长方式。

  1. 快速重传

通过重复 ACK 等信号尽早判断数据丢失并重传。

  1. 快速恢复

在某些拥塞控制算法中，检测到特定丢包信号后，不必重新从最小窗口开始增长。

注意：

不同 TCP 拥塞控制算法的具体行为可能不同。

TCP 是面向连接、可靠、面向字节流的传输层协议。

三次握手建立连接，典型四次挥手正常关闭连接。

SEQ 表示序列号，ACK 确认号表示下一个期望收到的字节序列号。

滑动窗口提高传输效率。

流量控制关注接收方，拥塞控制关注网络。

TCP 通过确认、重传等机制实现可靠传输。

什么是套接字（Socket）

一、什么是套接字（Socket）

套接字（Socket）是操作系统提供给应用程序进行网络通信的一种接口。

简单理解：

  • IP 地址：找到哪台计算机。
  • 端口号：区分计算机上的通信端点。
  • 协议：规定数据如何传输。
  • Socket（套接字）：让应用程序能够使用网络通信功能。

可以把 Socket 理解成应用程序与网络之间的一个“通信插座”。

注意：Socket 不是网络协议，而是应用程序使用网络协议进行通信的接口及其对应的操作系统资源。

6. 容易出错的知识点

错误一：Socket 是一种网络协议。

正确：Socket 是网络编程接口及对应的通信资源，不是协议。

错误二：Socket 只能使用 TCP。

正确：Socket 可以使用 TCP、UDP 等协议。

错误三：Socket 就是 IP 地址加端口号。

正确：IP 地址和端口号可以标识一个网络通信端点，但 Socket 还包含协议类型、状态等信息。

错误四：服务器只能通过一个端口连接一个客户端。

正确：服务器可以通过同一个监听端口接受多个客户端连接，并通过不同的连接 Socket 进行通信。

错误五：TCP 客户端必须手动绑定端口。

正确：客户端通常可以由操作系统自动分配临时端口。
